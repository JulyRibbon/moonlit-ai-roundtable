# Moonlit AI Roundtable 验收清单

> 适用版本：0.5.1（2026-11-11）
> 用法：逐项勾选；每项后面写证据（命令输出、文件行、截图路径、时间、操作者）。
> 本清单把“离线测试”和“真实场景”分开；两者不能互相替代。

## 0. 证据与声明规则

### 0.1 两类证据

- **离线证据**：`node --test` 通过、契约测试、存档/规则单测、静态资源测试。证明代码路径和契约，不证明某个真实客户端、模型或本机环境可用。
- **真实场景证据**：真实客户端、真实原生会话、真实模型回合、真实浏览器或真实 SSE 流。必须记录客户端版本、模型、房间、席位、时间和结果文件。

### 0.2 可声明支持的最低证据

| 想写的声明 | 最低证据 | 还不足以下结论 |
| --- | --- | --- |
| “离线契约通过” | 对应 `tests/contract/*.test.mjs` 或核心测试通过 | 真实客户端兼容、模型可用 |
| “本机单次跑通” | 1 次真实 completed 回合 + `attempts.jsonl` 终态 + 字幕正确 | 稳定性、重启恢复、异常路径 |
| “本机支持聊天” | 至少 3 个独立真实回合；含 1 次重启后继续；含 1 次 `[PASS]` 或 `@`；无重复/丢正文 | 长期稳定、所有模型/版本 |
| “本机支持某棋类” | 该棋类真实 AI 合法落子 + 刷新还原 + 重置；聊天字幕/attempt 数不变 | 所有规则分支、所有客户端 |
| “本机支持新客户端” | 契约测试 + 真实连接/身份/投递/终态/去重 + 失败可见 + 重启不重放 | 语音、用量、所有异常 |
| “稳定” | 多次真实回合、跨重启、停止/恢复、故障注入均符合预期 | 单次成功不能写稳定 |

### 0.3 硬规则

- [ ] 未实测的客户端/模型/能力，文档写“待测”或“不支持”，**不得写“兼容”“支持”“已适配”**。
- [ ] 单次成功只记录为“本机单次跑通”，不得写成“永久稳定”。
- [ ] 每条“支持”声明都能指到证据文件或命令输出；指不到就删掉声明。
- [ ] 文档、截图、日志示例里没有真实 token、Cookie、原生会话 id、私钥或个人信息。
- [ ] 验收过程不修改客户端人格、preset、模型、权限；房间只传共同事实。

## A. 部署与启动

- [ ] **A1 Node 版本正确** `[离线]`
  - 证据：`"%NODE24%" -v` 输出 `v24.21.0` 或 ≥22.13；记录实际路径。
  - 通过标准：不是 PATH 上的 Node 18.x。

- [ ] **A2 配置存在且可解析** `[离线]`
  - 命令：用 Node 24 运行 `server\live.mjs --help` 能打印用法；实际启动使用 `config/members.local.json`。
  - 证据：启动日志第一行 `[ai-room] config: ...`；没有 `CONFIG_MISSING`。
  - 检查：没有把真实 id 写进 `config/members.example.json`。

- [ ] **A3 全量启动成功** `[真实]`
  - 命令：`start-all.bat`。
  - 证据：`state\start-all.log` 含 `start-all ready`；浏览器能打开；`/api/health` 返回 200 与版本。
  - 检查：Kimi/Qwen 是复用还是本脚本拉起，记录清楚。

- [ ] **A4 只起房间的边界清楚** `[真实]`
  - 命令：`start.bat`，且 Kimi/Qwen 已单独启动。
  - 证据：房间起来；对应席位连接正常。
  - 反向检查：Kimi/Qwen 未启动时，房间不假装全部席位可用。

- [ ] **A5 席位连接与身份** `[真实]`
  - 证据：每个启用席位在界面显示连接状态和真实模型元数据；`rooms\<room>\attempts.jsonl` 无异常 identity 错误。
  - 检查：模型名来自客户端；不是配置里手写的占位值。

- [ ] **A6 端口无冲突** `[真实]`
  - 命令：`netstat -ano | findstr ":2961"`、`:58690`、`:58691`。
  - 证据：只有预期进程；没有误杀 DSH 2955/2960，没有碰 Qwen 桌面 App 现有实例（本机记录为 14306）。

- [ ] **A7 日志可定位** `[真实]`
  - 证据：`state\start-all.log`、`state\qwen-serve.log`、`state\audit.jsonl` 均存在且可读；知道轮转文件 `.1`。
  - 检查：日志里没有真实 token / 会话 id 被当成示例复制出来。

- [ ] **A8 停止语义正确** `[真实]`
  - 命令：`kill.bat --room r_main`，再 `kill.bat --all`。
  - 证据：`state\HALT.r_main` / `state\HALT` 出现；`state\audit.jsonl` 有对应记录；新派发停止；不可取消的客户端显示 degraded/pending。
  - 反向检查：没有把 halt 当成“进程已退出、端口已释放”。

- [ ] **A9 重启不自动续聊** `[真实]`
  - 操作：停止房间，重新 `start-all.bat`。
  - 证据：房间恢复字幕和历史；没有自动发起新回合；游戏轮到 AI 时停在“点击继续”。

- [ ] **B3 共享上下文** `[真实]`

  - 证据：精确回复 `[PASS]` 时产生 `MemberPassed`，不产生可见字幕；attempt 有记录。
  - 检查：正文里带解释的 `[PASS]` 不被误判为 PASS。

- [ ] **B5 `@` / 昵称指名** `[真实]`
  - 证据：被 `@seatId` 或昵称的席位优先接话；`mentions` 出现在事件/字幕记录；未知席位、自点名、邮箱不产生目标。

- [ ] **B6 本轮收尾** `[真实]`
  - 证据：其余可发言席位均 PASS，或机主新话题后全部 PASS，本轮进入 `review`；`maxAttempts` 只是硬上限。
  - 检查：失败/中止不计作 PASS。

- [ ] **B7 暂停/停止/恢复** `[真实]`
  - 证据：暂停只阻止新派发；停止尝试取消在飞请求；不能取消时显示 degraded/pending；恢复不自动续聊。
  - 检查：停止后没有新的模型调用。

- [ ] **B8 记录管理** `[真实]`
  - 证据：筛选、Markdown/JSON 导出可用；清空前生成 `rooms\<room>\backups\transcript-*.jsonl`；清空后 `transcript.jsonl` 为空，`events.jsonl` / `attempts.jsonl` 保留。
  - 检查：备份文件含真实会话引用时没有入库。

- [ ] **B9 计数管理** `[真实]`
  - 证据：导出包含排程、各席 completed/PASS/failed/aborted、消息数、选择序号、用量基线；重置前生成 `counters-*.json`；重置后字幕、attempt、原生会话不删除。
  - 检查：重置不会自动开新一轮。

- [ ] **B10 设置生效** `[真实]`
  - 证据：昵称、颜色、排序、每轮次数、共享上下文条数修改后原子写回；次数从下一轮生效。
  - 检查：没有改客户端人格/模型。

- [ ] **B11 用量展示的已知缺口** `[离线/真实]`
  - 证据：对照 `docs/known-gaps.md`；DSH 无 usage、GLM `attemptId` 为 null、Kimi 缺 `cacheRead` 仍是已知缺口。
  - 检查：没有把 null 写成 0，也没有声称已修复。

## C. 新客户端 / 新席位接入

## D. 游戏

- [ ] **D1.1 独立游戏会话** `[真实]`
  - 证据：四个 AI 位置各有独立 `game-<gameId>-<slot>` 会话；聊天专席引用未变。

- [ ] **D1.2 真实合法落子** `[真实]`
  - 证据：至少一个 AI 返回合法 `{"edge":"h:x:y","comment":"..."}` 并落子；附言显示在对应着法下。
  - 检查：附言没有进入主聊天字幕或 attempt。

- [ ] **D1.3 人类手动席** `[真实]`
  - 证据：人类点击空边可落子；非法边/已占用边被拒绝。
  - 检查：点击热区可用，不是只有细线可点。

- [ ] **D1.4 得分、连走、胜负** `[真实]`
  - 证据：围格得分、连走、40 边用完、最高分/平局至少各验证一个场景。
  - 检查：规则是 4×4 格子、5×5 点阵。

- [ ] **D1.5 刷新/重启还原** `[真实]`
  - 证据：刷新页面棋盘和附言恢复；重启房间后从 `games\dots-and-boxes.json` 还原；轮到 AI 时需点击“继续”。

- [ ] **D1.6 重置** `[真实]`
  - 证据：当前局未结束时确认；确认后新局开始；旧 AI 结果失效；旧原生会话保留。

## 附录：不得出现的写法

- “四个客户端都兼容”（没有逐一真实回合和版本记录）。
- “已修复用量统计”（`docs/known-gaps.md` 仍列缺口时）。
- “重启后自动继续”（当前语义是明确不自动续聊）。
- “DSH 支持语音”（当前无原生 TTS）。
- “游戏规则完整”（实际是简化规则）。
- “测试全绿所以客户端没问题”（离线测试不证明真实客户端/模型）。
- “跑通一次所以稳定”（单次成功不等于永久稳定）。
